# Void Drift — UI 방식 결정 (런타임 vs 에디터)

> onepage-design.md TODO #4 "인게임 UI 방식(UI Toolkit vs uGUI) 결정".

## 1. 결정

| 컨텍스트 | UI 시스템 |
|---|---|
| **런타임(인게임)** | **uGUI** |
| **에디터 커스텀 툴** | **UI Toolkit** |

컨텍스트별로 적합한 도구를 나눠 쓴다.

## 2. 근거

### 런타임 = uGUI
- **성숙·검증**: 모바일 터치 UI 레퍼런스, 서드파티 에셋, 애니메이션 생태계가 풍부.
- **월드스페이스 UI**: 데미지 넘버·(선택적)체력바 등 월드공간 UI가 확실.
  (UI Toolkit 런타임은 월드스페이스 등 일부가 uGUI만큼 성숙하지 않은 편 — 도입 시 버전 확인)
- HUD / 3choice 카드 / 스킬 버튼 등 이 게임의 런타임 UI 전부 uGUI로 무난.

### 에디터 = UI Toolkit
- 에디터 확장에 최적이자 Unity 권장 방향.
- 공고 1순위 "에디터 커스텀 툴" 정면 대응 → UI Toolkit 역량 증명 지점.

### 포폴 서사
- 두 UI 시스템을 **컨텍스트별로 분리 채택한 것 자체가 도구 선택 판단력** 어필.
- "에디터엔 UI Toolkit, 런타임엔 검증된 uGUI" → 근거 명확.

## 3. 런타임 UI 목록 (uGUI)

- HUD: 생존시간 / 점수 / HP
- 3choice 강화 선택 카드 (오브 습득 시 팝업)
- 실드 스킬 전용 버튼 (controls-design.md)
- 월드스페이스 후보(선택): 데미지 넘버 (체력바는 빨간 피격 연출로 대체 가능 → 도입 여부 추후)

## 4. 남은 과제

- HUD 레이아웃 상세 (가로 화면)
- 3choice 카드 비주얼/애니메이션
- 데미지 넘버 등 월드스페이스 UI 도입 여부 확정
