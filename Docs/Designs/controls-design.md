## 1. 플랫폼 / 자세

- **모바일, 가로형(landscape)**
- **한 손 조작 성립** — 사격이 오토라 연속 입력이 "이동" 하나뿐.
  (폰을 한 손으로 들고, 조작손 한 손으로 기동)

### 왜 모바일 유지인가 (전략)
- 타깃 그라비티(판교 DevHub) = 모바일 중심 퍼블리셔, 국내 시장도 모바일 선호.
- 포폴에 모바일 빌드가 1개뿐 → 모바일 = 포폴의 전략적 가치. 컨트롤 난이도로 버릴 이유 없음.

## 2. 입력 매핑

| 입력 | 방식 (모바일=주) | PC 보조 | 비고 |
|---|---|---|---|
| 이동 | **상대 드래그** (화면 어디서든) | **WASD / 화살표** | 드래그와 공존·합산 |
| 사격 | **오토** | — | 입력 없음, 정면 자동 사격 (뱀서라이크 문법) |
| 실드 스킬 | **전용 버튼** (코너) | **Space** | 버튼·Space 둘 다 동일 발동 (M4-4) |

## 3. 이동 — 상대 드래그

- 화면 임의 지점 터치 → 드래그 델타만큼 기체가 상대 이동.
- **절대좌표 방식 폐기 사유**: 손가락 밑에 기체가 고정돼 **기체가 손가락에 가려짐**.
  근접 회피가 핵심인 게임에서 치명적.
- 파라미터(감도 / 데드존 / 델타 스케일)는 Day5 튜닝.

## 4. 실드 스킬 — 전용 버튼 (더블탭 폐기)

- **더블탭 방식 폐기 사유**: 이동 드래그 중 더블탭이 밀림·오터치로 오작동 위험.
- **전용 버튼** 채택: discoverable + 오작동 없음 + 별도 입력 인식 시스템 불필요.
- 배치: 가로 화면 코너(조작손 반대편 또는 조작손 엄지 근처). 좌/우 배치는 옵션화 검토.

> 이 결정으로 "이동 드래그와 분리된 더블탭 입력 시스템" 파생 과제는 해소됨.

## 5. 화면 레이아웃 (가로) — 초안

- 이동: 전역 드래그(별도 조이스틱 UI 없음, 화면 어디든)
- 실드 버튼: 코너 고정
- HUD(생존시간/점수): **우측 상단** 간단 표기 / HP: 별도 표기 (progression-design.md·ui-design.md 연동)

## 5.5. PC 보조 입력 (모바일 원칙 유지, 데스크톱 플레이 보조)

- **원칙은 모바일**(§1). PC 입력은 에디터/Standalone에서 플레이·검증을 쉽게 하기 위한 **보조**이며 모바일 조작을 대체하지 않는다.
- **이동 = WASD / 화살표**: 드래그와 **공존(합산)**. 같은 이동 파이프라인(타깃 뷰포트 → 경계 클램프 → 속도 매핑)에 방향 입력을 더하는 방식이라 경계·일시정지 정합이 동일하게 적용된다. 속도는 파라미터(초당 뷰포트 분율, Day5).
- **실드 = Space**: 코너 전용 버튼과 **동일한 발동**을 공유(입력만 둘, 로직은 하나). 실드 메커니즘은 M4-4.
- **입력 백엔드**: New Input System **직접 디바이스 읽기**(`Keyboard.current`/`Pointer.current`, 액션 에셋 미사용) — 기존 드래그 입력과 동일 패턴. 레거시 `Input.*` 미사용.
