## I-1 · 플레이어 이동 관성감

- **상태**: 해결 (사용자 판단 — 현 이동감 수용, 튜닝으로 종결 2026-08-21)
- **관련**: M1-2, `Assets/Scripts/Player/PlayerMovement.cs`
- **발견**: 2026-08-17, M1-2 구현 중 (사용자 육안 확인)
- **증상**: 드래그로 빠르게 움직이거나 멈출 때 **관성처럼 미끄러지는 느낌**이 남는다.
- **경계 구분(중요)**: 함께 보고된 다른 두 문제는 **해결됨** — 경계 떨림(overshoot↔clamp 진동, 목표 선-클램프로 해결), 물리-회전 충돌(뱅킹을 자식 `Model` 비주얼로 이동해 해결). **이 "관성 이동"은 그 둘과 별개 원인**으로, 위 수정 후에도 남아 있음.
- **추정 원인(미검증)**:
  1. 뱅킹 회전 lerp(`bankLerpSpeed`)의 정착 잔상이 "미끄러짐"처럼 보일 가능성(=병진이 아니라 회전 잔상).
  2. 입력 누적(Update) → 소비(FixedUpdate)의 1프레임 지연.
  3. Rigidbody 속도 잔류 / 보간(interpolation) 영향.
- **조치 계획**: M1-2 손맛 튜닝 단계에서 **원인이 회전 잔상인지 실제 병진 관성인지부터 규명** 후 수정. (예: 회전 잔상이면 `bankLerpSpeed`/뱅킹 반응 조정, 병진 관성이면 속도 확정/보간 설정 점검.)
- **로그**:
  - 2026-08-17 — 이슈 등록(보류). 떨림·물리회전 충돌은 이 시점에 해결 완료.
  - 2026-08-21 — **해결**. 사용자가 현 이동감을 수용, 별도 수정 없이 튜닝으로 종결.

## I-2 · 플레이어 조준(Aim) 어색함

- **상태**: 해결 (튜닝으로 종결 — 사용자 결정 2026-08-21)
- **관련**: M1-3, `Assets/Scripts/Player/PlayerAim.cs`·`PlayerBanking.cs` — 상세 = [03_PlayerMovementAndCamera.md](03_PlayerMovementAndCamera.md)
- **발견**: 2026-08-20, M2-5 Play 검증 중 (사용자 육안). 적 스폰 배선은 정상.
- **증상**: 플레이어 조준(발사 축 정렬)이 **어색하게** 느껴진다. (구체 원인·조건은 미규명 — 추후 재현·분류 필요.)
- **조치 계획**: 나중에 교정. 조준 축 = 뱅킹 방향 기반(`PlayerAim`, 코 안쪽) — 어색함이 **조준 축 공식**(pitch/yaw 정렬)인지, **무타겟 직사 vs 원뿔 타겟 스냅** 거동인지, **뱅킹 연동**인지부터 규명 후 손맛 튜닝.
- **로그**:
  - 2026-08-20 — 이슈 등록(보류). 사용자 요청으로 이슈화, 교정은 후속.
  - 2026-08-21 — **해결**. 원인 = 카메라(뒤-원근) + 기체 +Z 정면이라 코너에서 소실점 방향 원근 단축, 그리고 조준 축(`PlayerAim`)이 기체 뱅킹과 별개로 계산돼 따로 노는 것. 조치: ①`FirePoint`를 `Model`(기체) 자식으로 이동해 **조준=기체 코 방향 단일화**(발사 위치=앞코) + `PlayerAim` 비활성, ②뱅킹 각 튜닝(`PlayerBanking` maxPitch/maxYaw 28→12, invertYaw로 바깥쪽). 카메라(탑다운화)는 사용자 반대로 미변경. 이후 미세 튜닝은 인스펙터(`PlayerBanking`)로.

## I-3 · 플레이어 체력 회복 수단 부재

- **상태**: 해결 (회복 수단 존재 확인 — 사용자 종결 2026-08-21)
- **관련**: M3-4/M4-8(3choice·업그레이드 풀), `Assets/Scripts/Player/PlayerHealth.cs`

## I-4 · 탄막 적 무제한 발사(교전 라인 게이팅 필요)

- **상태**: 해결 (Z-갭 교전 윈도우 게이팅 — 사용자 검증 2026-08-21)
- **관련**: M3-2(공격 AI), `Assets/Scripts/Enemy/AI/BarrageAttack.cs`(및 `AimedShot.cs`)
- **발견**: 2026-08-20, M4-1 Step2(유도 미사일) Play 검증 중 (사용자 육안).
- **증상**: 탄막(사격형) 적이 **스폰 직후부터 화면 이탈(despawn)까지 거리 무관하게 계속 난사**한다. 플레이어와 아주 먼 시점부터 쏴대서 탄이 과다.

- **조치 계획**: 후속. M4-5 난이도/스폰 튜닝 또는 M4-7 AI 정리와 함께 처리 가능. 지금은 파킹.
- **로그**:
  - 2026-08-20 — 이슈 등록(열림). 사용자 요청으로 이슈화("이슈화 시켜"). 구현은 후속.
  - 2026-08-21 — **해결**. `BarrageAttack`·`AimedShot` Tick에 **Z-갭 교전 윈도우** 게이트 추가: `dz = enemy.z − player.z`가 `[engageNearZ, engageFarZ]`(공용 기본값 10/60) 안일 때만 발사. 너무 멀면(>far) 침묵=먼 거리 난사 제거, 라인 통과해 너무 가까우면(<near) 발사 중지. 윈도우 밖에선 쿨다운 유지→진입 즉발. 값=Day5(생성자 기본값, 필요 시 `EnemyBuilder`에서 명시 전달). 사용자 Play 검증 정상.

## I-5 · 플레이어 라인 통과 오브젝트 페이드아웃 필요

- **상태**: 열림 (오브 페이드 구현 완료 · 시작선/완만함 튜닝은 나중 파킹 — 사용자 "되면 좋고 안되면 그냥")
- **관련**: `Assets/Scripts/Core/Orb.cs`. (**대상 = 오브만으로 축소 확정** — 적·적탄은 페이드 없이 유지, 대신 돌진 접촉 퇴장은 [I-6](#i-6--자폭-적-이동공격-ai-변경-및-자폭-vfx-필요)에서 별도 처리.)
- **발견**: 2026-08-21, 사용자 요청으로 이슈화.
- **증상/원하는 동작(사용자)**: 오브가 **플레이어가 있는 선(라인)을 지나면** 그대로 또렷하게 남아 화면 뒤로 빠지는데, 이를 **점점 흐려지게(페이드아웃)** 처리. 완전투명까지 갈 필요는 없고 "흐려짐이 인지될" 수준이면 됨.
- **머티리얼 조사 결과**: 적 비주얼=URP/Lit **Opaque**(알파 페이드 불가, 복제·투명전환 필요) → 비용 큼. 오브 비주얼=파티클 4종(Crystal/Glow/Sparks/Flares) 전부 **이미 Transparent**(URP/Particles) → MPB `_BaseColor` 알파로 즉시 페이드 가능. **이 난이도 차이가 "오브만" 축소 결정의 근거.**
- **구현(오브, z비례)**: `Orb.cs`에 통합 — 미캡처 드리프트 중 `orb.z < player.z + fadeStartOffset`부터 `alpha = 1 − past/fadeDistance`(`MaterialPropertyBlock`로 4개 파티클 렌더러 `_BaseColor` 알파, 원본×배수, 공유재질 안전). **캡처되면 `SetAlpha(1)` 복원**(자석에 끌려오면 다시 또렷). 반납은 기존 `z ≤ despawnZ` 유지(완전투명 불요). `OnSpawned`에서 알파 리셋(풀 재사용 잔상 제거).
- **튜닝값(인스펙터, Day5)**: `fadeStartOffset` 5(시작선을 플레이어보다 앞으로 당김)·`fadeDistance` 20(완만함). 0 이하면 페이드 비활성.
- **조치 계획**: 구현 완료. 흐려짐 시작 지점·정도는 위 두 값으로 나중 튜닝(사용자 파킹).
- **로그**:
  - 2026-08-21 — 이슈 등록(열림). 사용자 요청으로 이슈화. 구현은 후속.
  - 2026-08-22 — **대상 = 오브만 확정**(적 Opaque라 비용 큼, 오브는 이미 Transparent) + 오브 z비례 페이드 구현. 사용자 Play 관찰 "먼가 이상"하나 나중 튜닝으로 파킹(상태=열림 유지). `fadeStartOffset` 추가(시작선 앞당김).
