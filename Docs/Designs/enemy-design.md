## 1. 설계 원칙 — "고정 적"이 아니라 "조합형 적"

적을 3종으로 고정하지 않는다. **비주얼 아키타입 × 이동 AI × 공격 AI × 스탯**을
조합해 스폰하며, 그 조합 풀을 **Unity Editor 커스텀 툴에서 오서링**한다.

- 다양성: 3에셋 아키타입 × 4이동 × 4공격 → 조합 수십 종
- 에디터 툴이 단순 데이터 테이블을 넘어 **"조합 오서링 + 검증 툴"**로 격상
  (공고 1순위 "에디터 커스텀 툴" 정면 대응, CMDB 검증 경력과 서사 연결)

## 2. 적 엔티티 모델

적 인스턴스 = 아래 4요소의 조합.

| 구성요소 | 내용 |
|---|---|
| 비주얼(에셋) | 아키타입 3종 × 각 3에셋 = **9개 에셋 버킷** |
| 이동 AI | 직진 / 추적 / 사행 / 견제 (모듈, 재사용) |
| 공격 AI | 충돌 / 조준단발 / 탄막 / 자폭 (모듈, 재사용) |
| 스탯 | 체력·속도·데미지·드랍 오브량 (조합마다 주입) |

### 비주얼 아키타입 (3종)
전방(코스 안쪽)에서 플레이어 쪽으로 접근하는 구도 전제.

| 아키타입 | 성격 | 기본 교전거리 성향 |
|---|---|---|
| 탄막형 | 거리 두고 탄 뿌림 | 원거리 |
| 돌진형 | 체력 높고 느림, 몸통으로 밀고 들어옴 | 근거리 |
| 자폭형 | 체력 낮고 빠름, 붙으면 범위 폭발 | 근거리 |

> 돌진형 vs 자폭형 차별화: 돌진형은 몸통 단발 충돌(스치면 끝, 쏴서 처리 대상),
> 자폭형은 근접 시 **범위** 폭발(못 스치고 지나감, 미리 요격 대상).

## 3. AI 프리미티브

### 이동 AI
| 타입 | 동작 | 거리 성향 |
|---|---|---|
| 직진 | 코스 따라 곧장 접근 | 접근 |
| 추적 | 플레이어 XY 향해 보정하며 접근 | 접근 |
| 사행 | 좌우 사인파로 흔들며 접근 | 접근 |
| 견제(호버) | 일정 거리에서 코스 속도에 맞춰 머묾 | 거리 유지 |

### 공격 AI
| 타입 | 동작 | 요구 교전거리 |
|---|---|---|
| 충돌 | 발사 없음, 몸통 접촉 데미지 | 근접 필수 |
| 조준단발 | 플레이어 방향 한 발 | 무관 |
| 탄막 | 방사형/부채꼴 다발 | 원거리 선호 |
| 자폭 | 근접 시 폭발(범위 데미지) | 근접 필수 |

## 4. 유효성 규칙 — 차단 아님, **경고**

조합은 **자유롭게 선택 가능**. 단, "좀 아닌 것 같은" 조합은 툴이 **경고 표시**한다.
(강제 차단 X — 디자이너가 실험할 여지를 남김.)

핵심 규칙: **공격 AI의 요구 교전거리 ↔ 이동 AI의 거리 성향이 모순이면 경고.**

| 조합 예 | 판정 |
|---|---|
| 자폭 + 견제(호버) | ⚠️ 경고 (멀리 떠서 안 터짐) |
| 충돌 + 견제(호버) | ⚠️ 경고 (안 붙어서 충돌 안 함) |
| 탄막 + 추적 | OK (위협적이지만 유효) |
| 조준단발 + 아무 이동 | OK |

추가 경고: **에셋 라벨의 교전거리 ↔ 부여한 AI 성향 모순** (6절 참고).

## 5. 에디터 커스텀 툴 — 3층 구조

| 층 | 에디터가 관리 |
|---|---|
| 1. 유효성 경고 | 교전거리 모순 조합 / 라벨-AI 모순 → 경고 표시 |
| 2. 아키타입 프로파일 | 아키타입별 AI 성향 가중치 (예: 탄막형 = {탄막 70%, 조준단발 20%, 돌진 10%}) — **반쯤 묶기** |
| 3. 스폰 풀 | 난이도 구간별 어떤 프로파일을 어떤 가중치로 출현시킬지 |

> **반쯤 묶기**: 비주얼-AI를 완전 고정하지도(단조), 완전 자유롭게 두지도(비주얼 부조화) 않음.
> 아키타입별 기본 성향 + 확률적 변형을 **에디터 데이터로** 오서링.

## 6. 에셋 관리 (Addressables)

에셋 특성 관리는 **라벨(거친 분류) + ScriptableObject(정밀 데이터)** 병행.
라벨 하나로는 가중치·수치를 못 담기 때문.

| 계층 | 담는 것 | 용도 |
|---|---|---|
| Addressables **Group** "Enemy" | 적 프리팹(비주얼) | 빌드/번들 물리 묶음 |
| **Label** | `archetype:탄막/돌진/자폭`, `range:원거리/근거리` | 라벨 기준 일괄 로드·필터, 거친 특성 |
| **ScriptableObject DB** | AssetReference + AI 성향 가중치 + 스탯 범위 | 에디터 툴이 편집하는 디자인 원천 데이터 |

### 라벨 ↔ SO 교차 검증
라벨이 유효성 경고의 판정 근거가 된다.

- 에셋 라벨이 `range:근거리`인데 SO에서 그 에셋에 탄막(원거리) AI 프로파일을 주면 → ⚠️ 경고.
- 즉 라벨(빠른 로딩 인덱스) + SO(정밀 데이터)가 서로를 검증.

## 7. 스탯 필드 (Day5 수치, 테이블 툴 컬럼 후보)

- 체력 / 이동속도 / 데미지 / 드랍 오브량 / **처치 점수값**
- (공격 AI별) 발사 간격 / 탄속 / 탄막 수 / 자폭 반경 등

## 8. 확정 요약

- 비주얼 아키타입: 탄막형 / 돌진형 / 자폭형 (각 3에셋)
- 이동 AI 4종 / 공격 AI 4종 → 조합형
- 유효성: 교전거리 모순 = **경고(차단 아님)**
- 에디터 3층: 유효성 경고 / 아키타입 프로파일(반쯤 묶기) / 스폰 풀
- 에셋: Addressables Group + Label + ScriptableObject 병행, 라벨-SO 교차 검증
